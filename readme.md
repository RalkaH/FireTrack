# 🔥 FireTrack — Система отметки проверки средств пожаротушения

![Версия](https://img.shields.io/badge/Версия-1.1.0-blue)
![FastAPI](https://img.shields.io/badge/FastAPI-0.100+-009688?logo=fastapi)
![Python](https://img.shields.io/badge/Python-3.13-3776AB?logo=python)
![SQLite](https://img.shields.io/badge/SQLite-Database-003B57?logo=sqlite)
![Docker](https://img.shields.io/badge/Docker-Enabled-2496ED?logo=docker)

**FireTrack** — это автоматизированная система учета и контроля состояния первичных средств пожаротушения (огнетушителей) на промышленных, складских и административных объектах.

Проект предназначен для замены бумажных журналов проверок, автоматизации контроля технического обслуживания и формирования цифровой отчетности для внутренних проверок и надзорных органов.

Система помогает:
- минимизировать человеческий фактор;
- централизованно хранить данные об оборудовании;
- отслеживать сроки проверок и перезарядки;
- формировать отчеты в электронном виде;
- контролировать состояние противопожарного инвентаря;
- соответствовать требованиям ГОСТ Р 51057-2001 и ФЗ №123.

## 🚀 Основные возможности

*   **Учет огнетушителей:** Регистрация и хранение информации о каждом огнетушителе (тип, инвентарный номер, статус).
*   **Электронный журнал проверок:** Фиксация каждой проверки с сохранением метрик состояния оборудования.
*   **Контроль сроков обслуживания:** Автоматический расчет сроков ТО и отслеживание просроченных проверок.
*   **Дашборд и аналитика:** Главная панель для отображения общего состояния системы в реальном времени.
*   **Импорт и экспорт:** Поддержка загрузки и выгрузки данных (CSV, XLSX).

## 🗄 Структура базы данных

Связи организованы по правилам реляционных БД с поддержкой Foreign Keys. Основные таблицы:

- Users (Пользователи)
- Extinguishers (Огнетушители)
- Inspections (Проверки)
- Locations (Локации/помещения)
- Statuses (Статусы состояния)

---

## 🔐 Ролевая модель

В системе предусмотрено 3 роли доступа (RBAC):

| Роль | Возможности |
|---|---|
| admin | Полный доступ к системе, управлению пользователями и справочниками |
| engineer | Доступ к проведению проверок, добавлению и редактированию оборудования |
| viewer | Доступ только на чтение для просмотра аналитики и отчетов |

## 📥 Установка и запуск (Локально)

### Шаг 1. Клонирование репозитория

```bash
git clone https://github.com/RalkaH/FireTrack.git
cd FireTrack
```

### Шаг 2. Создание виртуального окружения и установка зависимостей

Для Windows (PowerShell):

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

Для Linux/macOS:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

Установка зависимостей:

```bash
pip install -r requirements.txt
```

### Шаг 3. Запуск приложения

```bash
python -m uvicorn main:app --reload
```

Приложение будет доступно по адресу: http://127.0.0.1:8000

## 📦 Сборка проекта (Setuptools)

Проект настроен для установки как полноценный Python-пакет.

Для сборки и локальной установки пакета в режиме разработки выполните:

```bash
pip install -e .
```

После установки приложение можно запустить через консольную команду (если настроено в setup.py):

```bash
firetrack-run
```

## 📚 Генерация документации (Sphinx)

Код проекта документирован с помощью Docstrings. Для сборки HTML-документации:

Перейдите в директорию документации:

```bash
cd docs
```

Соберите документацию (для Windows):

```powershell
.\make.bat html
```

Готовая документация будет доступна по пути: docs/build/html/index.html. Вы можете открыть её командой:

```powershell
start build\html\index.html
```

## 🐳 Развертывание через Docker

Для удобного развертывания проекта в облаке или на сервере подготовлены Dockerfile и docker-compose.yml. Все параметры конфигурации передаются через переменные окружения.

Запуск контейнеров в фоновом режиме:

```bash
docker compose up -d --build
```

Остановка контейнеров:

```bash
docker compose down
```

## 🔌 Примеры API запросов

### Авторизация (Получение токена)

**POST /auth/token**

*(Примечание: Используется формат Form-Data (application/x-www-form-urlencoded), а не JSON)*

```text
username=admin&password=admin123
```

Ответ:

```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "token_type": "bearer"
}
```

### Получение списка огнетушителей

**GET /extinguishers**

Требуется заголовок: `Authorization: Bearer <token>`

Ответ:

```json
[
  {
    "id": 1,
    "inventory_number": "OP-001",
    "type": "ОП-5",
    "status": "Актуально"
  }
]
```

## 🛡 Безопасность

В проекте реализованы современные стандарты безопасности:

- Ограничение доступа по ролям (RBAC).
- Защита маршрутов через JWT-токены.
- Надежное хеширование паролей (Bcrypt).
- Строгая валидация входящих данных через Pydantic.
